# V3 HTTP 预约突发测试（2026-11-12）

真实 Java17 + MySQL8.0.27 + Redis7.4.9 + RabbitMQ4.1.4，同一开发机。直接访问 Core HTTP；每档一次、无预热，非持续吞吐或数据库容量极限测试。每次创建新场次，容量固定25，200个独立用户。注册和最终状态轮询不计入入口延迟。

| 并发 | 入口 RPS | 平均 ms | P95 ms | P99 ms | HTTP 2xx | 限流 | 最终确认 | 业务拒绝 | 占用/容量 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 50 | 103.84 | 413.03 | 455.34 | 471.72 | 50 | 0 | 25 | 25 | 25/25 |
| 100 | 122.78 | 596.76 | 744.93 | 764.37 | 100 | 0 | 25 | 75 | 25/25 |
| 200 | 256.06 | 479.85 | 703.14 | 719.57 | 100 | 100 | 25 | 75 | 25/25 |

三组均检查 occupied_count 等于有效资格人数、没有超容量、没有同用户重复有效资格。当前脚本 responses.accepted 表示 HTTP 200/202，并不表示预约成功，数据库终态见 terminalStates。

200 并发有100个请求在 Redis 限流处拒绝，不能声称 MySQL 承担了200并发写入。上述入口 RPS 包含限流结果，不能视为预约成功 TPS。各组突发时间不足1秒，无统计稳定性和长期吞吐结论。没有优化前后对照数据。

未采集 MySQL 锁等待/慢SQL/连接池指标、Gateway/Sentinel 全链路、端到端完成延迟。尚未完成 CH01–CH19 全量验收。原有 HTTP 压测、数据集和报告保留。

运行：设置 V3_TEST_JAVA、V3_TEST_MYSQL 后执行 `python scripts/v3-p6/booking-load.py`。仅可用于隔离夹具，约定端口和账号见 v3-saga-acceptance.md。原始结果见 evidence/v3-http-bursts.json。
