# 核心实现说明

## 名额和资格

六状态：WAITING 不占名额，OFFERED/RESERVED/CHECKED_IN 占名额，CANCELLED/EXPIRED 为终态。占用字段只保存在 MySQL。生成列 active_guard 在有效状态取 1，终态为 NULL；唯一索引保障用户场次互斥，终态历史可以多条保留。重新报名必须新建资格，新请求标识；旧标识返回原资格，旧取消只处理旧 ID。

关键事务顺序是场次行锁、资格行锁、状态及计数更新、历史和 Outbox。活动整体取消先锁活动，再按场次 ID 升序锁定；预约不反向申请活动锁。重试事务必须重读时间和状态。预约满额不会自动进入候补，需用户明确选择。

队列序号在场次锁下递增并随事务提交，公平性是持久化入队顺序而不是网络请求到达顺序。取消和下一人补位同一事务；待确认已有名额，确认不再次扣减。确认截止为授予时刻加 10 分钟且不晚于报名截止/开始。到期后接口立即拒绝确认，数据库占用可在下一次维护任务后释放，不提前把未释放名额分配出去。

Redis Lua 只限新建资格。Redis 不可用返回 503，不新增本地锁或库存账本。查询缓存仅用于展示，数据库写入重新裁决。单场次行锁串行关键写，容量与竞争能力以实际压测证明，不预置吞吐目标。

## 消息

业务与 Outbox 同事务。发布器以既有 next_attempt_at/attempt_count 条件更新抢占短租约，事务外等待 RabbitMQ Confirm，并检查 mandatory Return 后标记 PUBLISHED。标记失败/租约过期允许相同event_id重发。通知事件ID/用户/类型唯一，通知行即幂等结果，无独立Inbox。Worker在数据库事务提交后手动ACK；可恢复失败经已确认的持久化重试副本后ACK，最多3次，之后隔离至DLQ。确认副本失败时保留原未ACK消息，关闭通道并按恢复间隔重建，不无限即时requeue。

普通失败有限重试后发 DLT；DLT 发送结果必须确认，否则保留原消息重试。没有端到端 Exactly Once 承诺。Outbox 一直保留，业务键也是提醒去重依据，不自动清理破坏幂等记录。

## 核销、评价与统计

随机 256 位不透明凭证关联具体资格，需管理员身份、场馆权限、场次匹配及合法窗口才能核销。唯一签到记录与 RESERVED→CHECKED_IN 同事务；占用不变。取消和核销共享场次锁，只能有一种合法结果。

正式预约统计不含 OFFERED，签到率以 RESERVED+CHECKED_IN 为分母。累计预约成功按历史转换统计，不等于人数。取消次数只统计正式资格的用户取消，不混入队列退出或管理员取消。评价只能在正常结束、已签到后提交，可修改但用户场次唯一。

不另建统计投影。当前版本汇总返回分场次数据，由界面展示；如需大范围查询，应先依据 EXPLAIN 和真实数据决定批量聚合优化，不伪造性能提升比例。

## 权限与 AI

JWT 标识用户，角色与场馆授权从数据库读取。管理 Service 对目标实体实际场馆校验。AI 工具只读且复用这些 Service/限定查询；策划只返回草稿预览，保存与发布分别经过普通管理入口。

导览中的活动数字由 Java 卡片查询，模型只给定性说明与引用。RAG 使用公开 Markdown，Chroma 是可重建索引；内存会话绑定认证用户并设窗口、过期与容量上限。复盘限定真实评价规模，Java 指标单独展示，模型不能输出指标字段。复盘支持场次与活动范围；活动汇总按人数加权计算签到率。

AI1 的增量编排采用 Alibaba Graph；五个只读图阶段之后，由用户选择场次并产生 MySQL 待确认方案。BookingExecute 在独立确认 HTTP 请求中执行，复用 Booking 与 ParticipationService。已提交结果查询在限流之前；新预约继续限流。Graph 状态、ChatMemory 和浏览器历史均不能授权写入，详见 `ai-graph-upgrade.md`。
