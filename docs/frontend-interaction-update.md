# 前端交互修复记录

本轮围绕已有业务页面修复交互，不引入前端路由框架、UI 组件库或其他依赖。

短时操作提示统一自动关闭：成功提示显示 3 秒，错误提示显示 6 秒，保留手动关闭按钮。连续出现新提示（包括相同文字）会重新计时；手动关闭和页面组件卸载时清理定时器。统计、AI 报告和其他业务结果不受提示计时影响。

## 页面与导航

- 探索活动的“查看场次”进入独立活动详情，展示活动介绍、报名须知和可操作场次。
- 文化场馆的“参观详情”进入独立场馆详情，展示地址、开放时间和介绍。
- 我的参与的电子凭证进入独立凭证页，展示二维码、核销码、状态与返回入口。
- 使用现有 Vue 和浏览器 History API 保存页面位置；详情链接含实体 ID，支持浏览器后退。
- 顶部导航及管理子导航高亮当前模块；面包屑、页面标题和说明标识当前位置。
- 页面切换滚动至顶部并聚焦标题；返回按钮保留来源页面，直接打开详情时回到对应列表。
- 每个列表独立维护页码，筛选重置至第一页。丢弃过期列表、详情和评价请求，避免快速切页造成内容覆盖或旧错误残留。

## 操作反馈

- 预约、候补确认、取消、保存评价提供成功或失败提示；处理期间显示加载状态。
- 根据场次时间及状态禁用不可执行的预约操作，最终结果仍由后端业务校验决定。
- 评价编辑读取本人已提交内容，提供“取消并返回”；保存后回到我的参与。
- 活动、场次和场馆编辑表单补齐取消返回入口；管理员统计与参与记录采用中文字段及表格展示。
- 候补待确认展示截止时间和倒计时；统计区分实时签到进度与结束后的最终签到率。

## 文件位置

- `web/src/main.js`：业务 API 调用、视图状态、History 导航及请求时序控制。
- `web/src/app-template.html`：用户和管理员页面模板。
- `web/src/interaction.css`：导航、详情、凭证、表格、反馈及窄屏样式。
- `web/src/DataView.js`：中文结果字段和表格。
- `culturehub-api/src/main/java/cn/culturehub/ApiController.java`：新增本人评价查询 GET `/sessions/{id}/my-review`，按当前登录用户限定。

## 实际验证与边界

执行 `cd web` 后运行 `npm run test:ui` 和 `npm run build`。

交互测试使用 Vue 自身的渲染器执行真实模板、按钮处理函数和视图切换，HTTP 响应为可控测试数据。覆盖详情切换、二维码生成、评价预填和保存返回、当前模块、浏览器后退、分页及过期请求隔离。它不能代替真实浏览器中的视觉布局和端到端验收。

另在运行中的本地 MySQL/API/Vite 环境验证真实活动场次、场馆详情、凭证、本人评价预填、其他用户评价隔离及密码 123 登录。结果见 `docs/evidence/ui-http.json`。后端 Maven 打包通过。未执行自动化真实浏览器布局验收；Docker、真实 Kafka、XXL-JOB Admin 和真实 AI 模型不属于本轮新增验证结果。

本机预览地址为 http://127.0.0.1:15173/ 。这个地址仅在本地进程运行期间有效。若浏览器仍保留旧页面，请按 Ctrl+F5 强制刷新。

## 第二轮细节完善

活动、管理活动与我的参与列表统一展示总条数、总页数、当前页及每页条数。新增计数接口复用列表的过滤和权限条件，空列表显示 0 页，下一页按钮按总数判断。

活动筛选增加所属场馆；文化场馆页增加名称/地址关键词和类型筛选。场馆类型是现有场馆资料的一个字段，可由平台管理员维护，未引入分类管理模块或额外表。新库 DDL 已包含该字段；已有数据库先执行 `deploy/migrations/20261101-venue-category.sql`，可重复执行。

场次编辑将原单个 datetime-local 控件改为六组日期与时刻输入，人数显式转换为数值。增加必填、正整数与时间关系校验，非法输入返回 400；已有参与历史时仍按原规则禁止修改。保存成功回到当前活动的场次列表。回归测试覆盖真实模板输入事件、提交数据与输入校验，另外使用真实 MySQL HTTP 测试检查新建与修改结果。

8 个场馆介绍及 30 个演示活动介绍、须知已扩写，知识文档同步更新。旧演示库可显式执行 `scripts/refresh-demo-content.py --database culturehub_rich_demo --port 13306`（按本地配置补充 `--mysql`）；该脚本仅允许专用 `_demo` 库，会覆盖目录中同名场馆与活动的介绍、分类和须知，不修改用户、资格、场次时间或名额。日常 API 启动不会反复覆盖管理员编辑内容。

新增本地 `.env` 模型配置入口，详见 `docs/ai-and-startup.md`。未填写密钥时保持 AI 关闭，普通业务启动不受影响。

第二轮真实 HTTP/数据库检查通过，记录在 `docs/evidence/ui-refinement-http.json`，复现脚本为 `scripts/verify-ui-improvements.py`。默认只读；`--write-demo` 须显式指定专用演示库，测试创建的临时草稿会在 finally 中清理，不删除现有活动。输入事件与前端结果记录在 `docs/evidence/ui-interactions.txt`。Maven package 与前端 production build 均通过；本轮没有真实浏览器布局验收或真实模型调用。

## 场馆授权交互

管理工作台的管理员授权改为选择账号/昵称后，按场馆名称勾选。自动读取原有授权，显示完整选择结果，按名称或地址过滤场馆不会清除隐藏项的勾选。支持撤销未保存修改；取消全部勾选后保存需要确认，保存仍使用原有 PUT 接口提交数字 ID 数组。

平台管理员已有全局权限，用户选择项中明确说明，不需要分配场馆。普通账号分配场馆后由原业务授予场馆管理员角色。清空场馆授权仅清空管理范围，保留原有角色模型，不修改其他用户授权。

场馆管理卡片和授权选项均展示辅助编号；无需手工抄录编号完成授权。新增已有授权读取接口仅供平台管理员调用。用户切换时清空旧勾选并读取新数据，过期响应不会覆盖当前用户；读取失败时禁止保存并提供重试。

## 取消后的活动列表

取消是保留关联记录的状态转换，不物理删除活动。原管理列表包含全部状态，导致取消成功后仍显示卡片。现在管理列表默认 ACTIVE（未取消），已取消活动从默认管理列表移除；可通过“已取消”或“全部状态”查询历史。公开列表和详情始终仅返回已发布活动。列表与总数共用状态过滤和权限条件，取消后刷新数据；若当前页已超出末页，自动回到有效页码。已取消卡片禁止编辑、发布和重复取消。

Vue 交互回归覆盖取消后的列表移除、总数更新、最后一页回退及历史筛选；本地真实 API/MySQL 的只读核对记录见 `docs/evidence/activity-cancellation.json`，保留了用户原先取消的活动，未修改其数据。
